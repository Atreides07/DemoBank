# Локальный кеш

`CacheStore(namespace: 'responses')` создаёт нативный Drift-кеш. Конструктор не открывает БД и не запрашивает платформенный каталог; первая операция лениво создаёт файл в Application Support. SQL выполняется в изоляте через `NativeDatabase.createInBackground`. SQLite для Android поставляется `sqlite3_flutter_libs`. Для интеграционных тестов можно передать отдельный `path`.

На web условный импорт использует `localStorage`; при запрете или заполнении хранилища доступен ограниченный кеш сессии. Для unit-тестов явно внедряется `MemoryCacheStore`. Во всех реализациях интерфейс одинаков:

```dart
final store = CacheStore(maxEntries: 120);
await store.write('transactions/main/october/page-1', response,
    ttl: const Duration(minutes: 5), revision: '2');
final entry = await store.read('transactions/main/october/page-1');
// entry.value, writtenAt, expiresAt, revision, isFresh
await store.expireAll(); // Данные сохранены и явно устарели.
await store.clear();     // Пустой кеш для первоначальной загрузки.
await store.close();
```

Ключ кеша задаётся репозиторием и включает фильтры/страницу; версия и актуальность сохраняются внутри записи. Устаревшие данные доступны для немедленного показа с фоновым обновлением. Предел — 120 записей LRU по умолчанию, каждая до 1 МиБ; репозитории задают собственный предел загруженных моделей. Кеш не содержит токены и секреты. Статус незавершённого платежа не следует считать подтверждённым ответом кеша: его проверяет процессинг.

Контрактные проверки памяти и Drift охватывают свежесть, сохранение устаревших данных, принудительное устаревание, LRU, удаление, закрытие и восстановление после переоткрытия SQLite. Запуск: `flutter test packages/local_storage/test`.

Платёжный журнал и сохранённый процессинг используют отдельный `CacheStore(namespace: 'journal')`: отдельный файл БД/префикс web. Он не участвует в очистке и вытеснении ответов. Время жизни таких записей задаётся отдельно от пятиминутного кеша.
