Это бюджетный Android, но результат на 3–4 ГБ не проверен. `benchmarkLive` + `traceAction` сохраняют сырые `traceEvents`; необходим `flutter drive --no-dds`. Методика и неизменные цели — в [performance.md](performance.md).

Framework shell после `pumpWidget`, cold/cache data-ready, API complete → framework frame и Android Activity TotalTime — разные величины. Data-ready не гарантирует видимость нужной строки. Handler → framework frame исключает системную доставку ввода и физическую презентацию пикселей. `FrameTiming` не является системным счётчиком пропущенных обновлений дисплея. Порог **<1%** относится к воспроизводимому **60-секундному scroll**, дополнительный обязательный per-stage <1% gate не вводится. Сценарный `passed` не означает попадание всех interaction p95/p99/max в бюджет.

Native input измеряется от `CLOCK_MONOTONIC` перед `exec input tap` до первого последующего actual-present собственного Flutter SurfaceView после проверки idle. Это верхняя граница с запуском input/dispatch, не физический палец, подтверждённое назначение, вся анимация или готовность сети. Android **HOT** после HOME не называется WARM. Инструментированный RSS удерживает трассы и не равен ordinary PSS; шесть ограниченных циклов и lifecycle/page bounds не являются lifetime leak proof. [OS-сборщик](../tool/measure_android_release.py), [нативный marker](../tool/android_input_marker.c) и [21 регрессия](../tool/tests/test_measure_android_release.py) входят в репозиторий.

`ApiClient.persistentConnection` по умолчанию **true**. Явный `HTTP_KEEP_ALIVE=false` — DI-режим совместимости; в profile/AOT записывается **фактическое** значение созданного клиента, в simulation — `null`. UI и репозитории политику не выбирают. [Loopback-тесты](../packages/network_client/test/connection_policy_test.dart) подтверждают default: одно TCP, request-close: три для GET/POST/503, POST ровно один, typed cancellation открытого тела и восстановление обоих режимов. [ADR 0006](adr/0006-http-connection-policy.md) фиксирует стоимость дополнительных соединений; всего ADR шесть. HTTPS-успех compatibility-режима не объявляется исправлением исходного pooled-поведения или доказательством причины сетевого сбоя.
