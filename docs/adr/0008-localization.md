# ADR 0008: один каталог строк, тексты сервера по Accept-Language

Решение от 18 октября 2026 года. Приложение поддерживает ru, en и uz. Подробности — в [localization.md](../localization.md).

**Один пакет `app_localizations`** для всех фич и оболочек вместо каталога в каждом пакете. Общие формулировки (повтор, комиссия, ошибки платежа, категории) не дублируются, а переводчик работает с тремя файлами. Цена — «Штрафы» тянут каталог целиком (несколько десятков КБ строк); граница фич по коду при этом сохраняется, quality gate по-прежнему запрещает зависимость `fines_app` от банковских фич. `design_system` держит свои немногие слова в `DsLocalizations`, чтобы не зависеть от продуктового пакета.

**Кодов, а не текстов в состояниях.** Cubit и домен отдают перечисления и коды, текст выбирает экран. Это позволяет переключать язык без перезагрузки состояния и тестировать логику без строк.

**Тексты сервера — на сервере.** Названия счетов, операций, начислений и сообщения отказа приходят на языке `Accept-Language`, как это сделал бы реальный бэкенд. Хранимое состояние демо-сервера языконезависимо; кеш ответов разделён по языкам. Клиентские категории и подписи графиков берутся из каталога клиента, чтобы фильтры и диаграммы совпадали с остальным интерфейсом.

**Форматирование из минорных единиц.** `AppFormats` строит суммы из целых копеек/тийинов и символов `intl`, а не через `NumberFormat.currency` с `double`, чтобы округление никогда не меняло сумму.

Пересмотреть решение при появлении языка с письмом справа налево (потребуются RTL-проверки макетов) или реального бэкенда с собственным каталогом сообщений.
