# ADR 4: общий checkout и восстанавливаемый процессинг

Решение: quote → подтверждение → идемпотентное создание → проверка серверного статуса → receipt/ticket. Pending journal отделён от response cache и привязан к backend/seed. Симулятор и сетевой сервер используют один DemoApi.

Причина: потеря ответа не доказывает отказ, повторное действие не должно списывать дважды, уход с экрана и перезапуск должны сохранять возможность выяснить результат.

Последствия: создание операции резервируется атомарно, повтор использует тот же ключ, pending отображается отдельно от success. Состояние локального demo backend сохраняется независимо от кеша. Настоящие провайдеры и реальные деньги остаются за рамками проекта.
