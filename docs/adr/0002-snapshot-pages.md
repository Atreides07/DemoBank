# ADR 2: snapshot-пагинация с ограниченными окнами

Решение: 30 записей, серверная revision, непрозрачный cursor, до пяти полных страниц в памяти. Лёгкие стабильные ID/даты сохраняют адресацию посещённых слотов. Сервер предоставляет согласованное окно вокруг anchor ID и адресацию страницы внутри фиксированной revision.

Причина: новые операции не должны создавать дубликаты, сдвигать чтение или вынуждать скачивать десятки страниц до далёкого якоря. Один lazy-list не ограничивает память моделей.

Последствия: сервер хранит ограниченную историю snapshot-версий; клиент явно обрабатывает истечение revision. Старое содержимое остаётся до готовности нового окна. Фоновое поступление новых данных предлагает явное применение. Аналитические агрегаты и детализация используют одну revision.
